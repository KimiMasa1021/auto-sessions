# 出来事ごとの対応の選択肢

セットアップで出来事ごとに1つ選んでもらい、選ばれた「子への指示」を `templates/child.md` の `{{ACT_REQUEST}}` `{{ACT_REREQUEST}}` `{{ACT_COMMENT}}` `{{ACT_APPROVE}}` にそのまま入れる。

- 「セッションを作らない」を選んだ出来事は、子への指示に `（この kind ではセッションを作らない設定。届いたら、その旨だけ答える。）` を入れ、親の `{{SKIP_KINDS}}` にその kind を入れる。
- 「Other」で自由に書かれたら、その文をそのまま子への指示にする。ただし、GitHub への書き込みや push を求める内容なら、手順 4 の決まりで行わないことを伝え、書き直してもらう。
- `{{WORK_DIR}}` は、チェックアウトを選んだときにだけ聞くフォルダ（例: `~/src`）に置き換える。

## request（[レビュー依頼]）

| 選択肢 | 子への指示 |
|---|---|
| 要約と見るべき点を書く (Recommended) | レビューで見るべき点（変更の大きいファイル、リスクのありそうな箇所）と、確認したいことを書く。 |
| レビューコメント案まで下書きする | 見るべき点を書いたうえで、ファイルと行を示したレビューコメント案を下書きする。GitHub には投稿しない。 |
| ブランチをチェックアウトして待つ | 見るべき点を書き、PR のブランチを {{WORK_DIR}} の下に用意して、そのパスを伝える（用意のしかたは手順 4 の決まりに従う）。 |
| セッションを作らない | （この kind ではセッションを作らない設定。届いたら、その旨だけ答える。） |

## rerequest（[再レビュー]）

| 選択肢 | 子への指示 |
|---|---|
| 前回の指摘への対応状況を書く (Recommended) | 前回の自分のレビュー以降に何が変わったかと、前回の指摘それぞれに対応されたかどうかを書く。 |
| 追加のコメント案まで下書きする | 対応状況を書いたうえで、まだ足りない点や新しく気になる点について、ファイルと行を示したコメント案を下書きする。GitHub には投稿しない。 |
| 最新のブランチをチェックアウトして待つ | 対応状況を書き、PR の最新のブランチを {{WORK_DIR}} の下に用意して、そのパスを伝える（用意のしかたは手順 4 の決まりに従う）。 |
| セッションを作らない | （この kind ではセッションを作らない設定。届いたら、その旨だけ答える。） |

## comment（[指摘あり]、自分の PR）

| 選択肢 | 子への指示 |
|---|---|
| 指摘の一覧と対応案を書く (Recommended) | 新しく付いた指摘の一覧（誰が、どのファイルの何行目に、何を）と、それぞれへの対応案を書く。 |
| 修正案を差分で下書きする | 指摘の一覧を書いたうえで、それぞれの修正案を unified diff の形で書く。ファイルは変えない。 |
| ブランチをチェックアウトして待つ | 指摘の一覧を書き、PR のブランチを {{WORK_DIR}} の下に用意して、そのパスを伝える（用意のしかたは手順 4 の決まりに従う）。 |
| セッションを作らない | （この kind ではセッションを作らない設定。届いたら、その旨だけ答える。） |

## approve（[Approve]、自分の PR）

| 選択肢 | 子への指示 |
|---|---|
| マージ前の確認事項を書く (Recommended) | 誰が Approve したか、ほかに未解決の指摘が残っているか、マージの前に確認することを書く。 |
| マージできるか判定する | 誰が Approve したかに加え、gh pr checks の結果、コンフリクトの有無、未解決の指摘を調べ、「マージできる / できない（理由）」を一行で結論づけてから詳細を書く。マージはしない。 |
| 通知だけ | PR を読まない。「<repo>#<pr> が Approve されました。https://github.com/<repo>/pull/<pr>」とだけ書く。 |
| セッションを作らない | （この kind ではセッションを作らない設定。届いたら、その旨だけ答える。） |

## {{WORKSPACE_RULE}} に入れる文

- チェックアウトを1つでも選んだとき:
  `ただし、kind の対応にチェックアウトがあるときに限り、{{WORK_DIR}}/<repo の name 部分> で次だけを行ってよい: フォルダがなければ gh repo clone <repo> で作る。あれば git fetch する。続けてそのフォルダで gh pr checkout <pr> -R <repo> を実行する。作業中の変更があって切り替えられないときは、変更に触らずにそう報告する。`
- 選ばなかったとき: 空文字にする。
