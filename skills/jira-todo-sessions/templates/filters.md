# 検知する課題の絞り込み

セットアップで「期間」と「担当者」を1つずつ選んでもらい、それぞれの JQL を `AND ` で始めて末尾に空白を付けた形でつなぎ、`templates/parent.md` の `{{FILTERS}}` に入れる。どちらも条件なしなら空文字にする。

例: 今のスプリント ＋ 自分にアサイン → `AND sprint in openSprints() AND assignee = currentUser() `

`currentUser()` は、親が使う Atlassian コネクタでログインしているアカウントになる。普段 Jira で課題をアサインされるアカウントと違うことがある（別のメールアドレスでコネクタをつないだときなど）。「自分」を含む選択肢を選んだら、試しの検索の結果に入っている `atlassianAccountId` を `lookupJiraAccountId` で調べ、名前を見せて「このアカウントで合っていますか」と確かめる。違えば「特定の人」で普段のアカウントを指定してもらう。

## 期間

| 選択肢 | JQL | 補足 |
|---|---|---|
| 今のスプリント (Recommended) | `sprint in openSprints()` | スプリントを使っていないプロジェクトでは、試しの検索でエラーになるか 0 件になる。そのときは別の選択肢を選び直してもらう |
| すべての期間 | （条件なし） | ステータスが合えば、いつ作られた課題でも対象になる |
| 最近作られたもの | `created >= -<日数>d` | 日数を聞く（既定は 14） |
| 期間を指定 | `created >= "<開始日>" AND created <= "<終了日>"` | 開始日と終了日を `YYYY-MM-DD` で聞く。終了日を過ぎると新しい課題は対象外になることを添える |

「Other」で JQL の条件を直接書かれたら、そのまま使う。ただし `ORDER BY` や、`project`・`status`・`labels` の条件は含めない（ほかの部分と重なるため）。

## 担当者

| 選択肢 | JQL | 補足 |
|---|---|---|
| 自分にアサインされたもの (Recommended) | `assignee = currentUser()` | チームで使うときの基本。目印のラベルは全員で共有なので、絞らないと最初に見つけた人の PC にだけセッションができる |
| 自分か未アサイン | `(assignee = currentUser() OR assignee is EMPTY)` | 未アサインの課題は、同じ設定のメンバーのうち最初に見つけた人の PC にできる |
| 担当者で絞らない | （条件なし） | 1人で使うときや、自分がまとめて受けるとき向け |
| 特定の人 | `assignee in (<accountId>, ...)` | 名前かメールアドレスを聞き、`lookupJiraAccountId` で accountId に変える。見つからなければ聞き直す |
