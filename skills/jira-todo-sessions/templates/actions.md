# 子にさせることの選択肢

セットアップで1つ選んでもらい、選ばれた「子への指示」を `templates/child.md` の `{{ACTION}}` にそのまま入れる。

- 「Other」で自由に書かれたら、その文をそのまま子への指示にする。ただし、Jira の編集や push を求める内容なら、手順 4 の決まりで行わないことを伝え、書き直してもらう。
- `{{REPO_DIR}}` は、「作業の準備まで」を選んだときにだけ聞く、リポジトリのフォルダ（手元にクローン済みのもの）に置き換える。

| 選択肢 | 子への指示 |
|---|---|
| 頭出しだけ (Recommended) | はっきりしない点・確認したいことと、進め方の案（3〜5ステップ）を書く。 |
| 下書きまで | はっきりしない点・確認したいことを書いたうえで、実装方針（変えるもの、変えないもの、気をつける点）と、作業の分解（1つが半日以内になるくらいのタスクの一覧）を書く。 |
| 作業の準備まで | 進め方の案を書き、{{REPO_DIR}} に課題キーと同じ名前のブランチを用意して、そのパスとブランチ名を伝える（用意のしかたは手順 4 の決まりに従う）。 |

## {{WORKSPACE_RULE}} に入れる文

- 「作業の準備まで」を選んだとき:
  `ただし、{{REPO_DIR}} で次だけを行ってよい: git fetch したうえで、課題キーと同じ名前のブランチがあれば git switch で切り替え、なければ既定のブランチの最新から git switch -c で作る。作業中の変更があって切り替えられないときは、変更に触らずにそう報告する。`
- ほかを選んだとき: 空文字にする。
